# tiny-tui V1 Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement V1 of tiny-tui — a minimal terminal UI library for let-go with pure widgets (list, confirm), a small program loop, and high-level `select`/`confirm` helpers — following `docs/tiny-tui-initial-design.md` stages 0–8.

**Tech Stack:** let-go (`.lg` sources, run via `lg`/`lgx`), built-in `term` namespace for terminal I/O, `clojure.test` via `lgx test`, `cljfmt` via `lgx fmt`.

## Design

### Architecture

Pure widgets + one effectful loop, the model proven by legmacs (`../legmacs`):

```text
state + key message -> new state + event   (pure)
state -> rendered string                   (pure)
terminal I/O                               (only in tiny-tui.screen and tiny-tui.key/read)
```

Widgets never touch the terminal. `core/run` owns the loop: render the view, read a key, call `update`, repeat until `update` returns a non-nil event. Everything except `screen` and `key/read` is unit-testable without a TTY.

### What let-go's `term` namespace provides (verified in `../let-go/pkg/rt/term.go`)

`raw-mode!`, `restore-mode!`, `read-key`, `key-pending?`, `size`, `tty?`,
`alternate-screen`, `main-screen`, `hide-cursor`, `show-cursor`, `clear`,
`clear-line`, `move-cursor`, `write`, `write-at`, `flush`.

Note: `term/set-fg`, `term/bold` etc. **write escape codes directly to stdout** —
the wrong shape for pure string-returning views. tiny-tui builds its own ANSI
strings instead (see Key decisions).

`term/read-key` returns string tokens: full escape sequences arrive as a single
token (e.g. ESC + `[A` for the up arrow), lone ESC as just ESC, printables as
one-character strings.

### Key decisions

1. **Style builds ANSI strings in-library.** `style/fg` etc. wrap text in SGR
   sequences built with `(char 27)` — never literal control characters in
   source (see Gotchas). Named colors map to portable 16-color SGR codes
   (30–37 fg, 90–97 bright fg, 40–47/100–107 bg); an integer color passes
   through as 256-color (`38;5;N` / `48;5;N`).
2. **Key messages** are keywords for special keys (`:up` `:down` `:left`
   `:right` `:enter` `:tab` `:esc` `:backspace` `:delete` `:home` `:end`
   `:ctrl-a`…`:ctrl-z` including `:ctrl-c`) and one-character strings for
   printables (`"q"`, `"d"`). Byte 7 (BEL) is `term/read-key`'s resize
   wake-up *and* a literal Ctrl-G — map it to `:resize`, which every loop
   treats as a no-op redraw. No Alt/meta combos in V1 (a lone ESC token is
   just `:esc`).
3. **Frame rendering:** move cursor home, then each line + clear-to-end-of-line
   (`ESC[K`), joined with `\r\n` (raw mode needs `\r`), then clear-below
   (`ESC[J`). No full `term/clear` per frame (kills flicker), no diff renderer.
4. **Always alternate screen** while a TUI is active — the user's shell content
   reappears untouched after `tui/select` returns. Cursor hidden while active.
5. **`run` exits on any non-nil event** from `update` and returns
   `[final-state event]`. The design doc's `:quit` is just one such event; this
   generalization is what lets `select` terminate with `{:type :select …}`
   without a side channel. `run` handles `:ctrl-c` itself (returns
   `[state :ctrl-c]` without consulting `update`) so there is always an escape
   hatch, and treats `:resize` as a redraw no-op.
6. **`run` injects terminal size** as `:tui/size [cols rows]` into the state
   before each `view` call (fallback `[80 24]`), so views stay pure but can
   truncate to the terminal width.
7. **Testing hooks on `run`:** optional `:read-key-fn` (default
   `tiny-tui.key/read`), `:render-fn` (default `screen/render!`), and
   `:screen false` to skip terminal setup. Tests drive whole `select`/`confirm`
   flows headlessly with scripted key sequences.
8. **`screen/init!` throws** (`ex-info`) when stdout is not a TTY — a library
   must not `os/exit` the host process. `with-screen` (a macro; `defmacro`
   verified working) guarantees cleanup via `try`/`finally`: restore raw mode,
   show cursor, reset style, return to main screen, flush.
9. **Confirmation UX: a plain yes/no list, no popup.** The confirm widget is
   a thin wrapper over the list widget: title, message, then a two-entry list
   (confirm-label / cancel-label). Arrows + enter select; `y`/`n` work as
   shortcuts; `esc` cancels. No box, no centering, no overlay — this resolves
   the design doc's open question toward the simplest option (popup dropped
   as too complex for this stage). Inside `select`, confirmation is still a
   full-frame view swap on `{:mode :confirm}`.
10. **Events** are the design doc's shapes: `{:type :select :item i :index n}`,
    `{:type :action :action id :item i :index n :destructive? b}`,
    `{:type :confirm :value bool}`, `{:type :cancel}`, plus plain `:quit` for
    custom apps.

### Public API (end state)

```clojure
(tui/select {:title "…" :items […] :item->text :name :actions […]})
;; => {:type :select|:action|:cancel …}

(tui/confirm {:title "…" :message "…" :confirm-label "…" :cancel-label "…"})
;; => true | false

(tui/run {:init state :update (fn [state msg] [state event]) :view (fn [state] "…")})
;; => [final-state event]
```

### Testing strategy

`clojure.test` via `lgx test` (auto-discovers `test/**/*_test.lg`). Pure
functions get direct assertions: `update` functions checked as
`[state event]` data, views checked as string equality (snapshot style —
compare against expected multi-line strings built with `string/join`).
`select`/`confirm` flows get headless end-to-end tests through `run`'s testing
hooks with scripted key sequences. Real-terminal behavior is verified manually
by running the examples.

### let-go gotchas (from legmacs, apply throughout)

- **No forward references at top level.** Order `def`/`defn` bottom-up within
  each namespace, or `(declare …)`.
- **Never write literal control characters or `\uXXXX` escapes for them in
  `.lg` source through file-editing tools** — they can be decoded into raw
  bytes on disk. Build them at runtime: `(def ESC (char 27))`. Check with
  `od -c <file>` if in doubt.
- **Namespace resolution is cwd-relative.** Run `lg`/`lgx` from the repo root.
- **Guard executable top-level forms** with `(when-not *compiling-aot* …)`
  (see existing `main.lg`).
- `term/char-width` is currently a stub returning 1 — Unicode width handling
  is explicitly out of scope for V1 (use plain `count` on stripped strings).

## File Structure

```text
src/tiny_tui/
  style.lg      ANSI text styling: fg, bg, bold, dim, inverse, styled, strip, visible-width  (pure)
  layout.lg     lines, vstack, hstack, pad, box                                              (pure)
  help.lg       view: bindings -> one help line                                              (pure)
  key.lg        parse (pure raw token -> message), read (blocking I/O)
  screen.lg     terminal ownership: init!, shutdown!, clear!, render!, with-screen, frame-str
  list.lg       list widget: create, update, view, selected-item, selected-index             (pure)
  confirm.lg    confirm widget: create, update, view — thin wrapper over list                (pure)
  core.lg       public API: run, select, confirm

test/tiny_tui/
  style_test.lg  layout_test.lg  help_test.lg  key_test.lg
  list_test.lg   confirm_test.lg  core_test.lg
```

## Implementation summary (completed 2026-07-02)

All nine tasks are done: 61 tests / 139 assertions pass via `lgx test`, and
all six examples were driven end-to-end under a pseudo-TTY (`script` +
scripted key bytes), covering select, cancel (q/esc/Ctrl-C), actions, and
both confirmation outcomes.

Deviations from the plan, all forced by let-go/runtime behavior discovered
during implementation:

- **`term/tty?` requires a handle argument**, so `screen/init!` detects
  "not a terminal" via `(nil? (term/size))` (legmacs's approach) instead.
- **LF also maps to `:enter`** (plan said CR only): input that passes
  through a cooked-mode tty or pipe arrives as LF, and real terminals in
  raw mode send CR — mapping both costs nothing and makes piped input work.
- **let-go `try` semantics broke the planned `with-screen`:** a `try`
  without `catch` returns the thrown value instead of propagating, and a
  `catch` that rethrows skips the `finally`. `with-screen` is now a macro
  over `with-screen*`, which captures the outcome as `[:ok v]`/`[:err e]`,
  always runs `shutdown!`, then returns or rethrows. Verified under a pty:
  a throwing body restores the terminal and surfaces the error.
- **`term/size` can report `[0 0]`** on an unconfigured pty; `run` falls
  back to `[80 24]` whenever either dimension is not positive.
- **Width truncation only applies to plain item text.** Truncating
  ANSI-styled text by raw index could cut inside an escape sequence
  (codex-review finding), so styled text is rendered untruncated.
- **`lgx build` was dropped from the README**: it needs a `:targets`
  entry that the scaffold never had, and a library has no binary to ship.
- Task 6's immediate-return test for destructive actions was superseded in
  Task 8, where `:destructive?` began implying confirmation.

Each task was reviewed by a codex second-opinion pass; its confirmed
findings (falsey list items not selectable, raw-mode leak on partial init
failure, committed `.tmp` review artifacts, stale docstring, styled-text
truncation) were fixed and committed alongside the tasks.
